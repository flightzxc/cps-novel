# ADR-PN15：前台站内搜索（只搜书名、分页、复用 B-38 列表筛选）

- 状态：已采纳（Owner 2026-10-09 拍板，主控转达，原话见下"拍板结果"）
- 日期：2026-10-09
- 范围：v0.5.14；分支 `feat/pn15-search-v0514`（第一批：搜索查询、搜索页、收录与分享卡片、语种切换、15 语文案、nginx 模板；后台开关在 `feat/pn15-switch-v0514`，页头入口等设计稿选定后第二批）
- 方案全文：`产品原型及文档/cps海阅/方案_PN15站内搜索_v0.5.14_2026-10-09.md`
- CPS 参照：`cps-admin` tag `v8.1.0`、`v8.1.1`、`v8.1.2`、`v8.4.0`、`v8.7.2`（生产线）

## 背景

海阅前台没有站内搜索：读者只能翻"全部作品"（B-38 之后可翻到全部 3 万余本）或按题材分类。CPS 短剧站自 v8.1.0 起有站内搜索，海阅的"能照搬短剧站流程的尽量照搬"（Owner 纲领）适用。

## 拍板结果（Owner 2026-10-09）

原话："可以提供搜索功能，也没必要禁止抓取，更没必要把搜索结果页写入站点地图，顺其自然。5 项都同意建议。4 入口可以看 cps，但是最好要调用 claude design 先设计一稿，因为之前做，适配小屏的时候按钮不是很自然。你看看要不要。5 开关加，最好做在后台。"

1. **收录照 CPS v8.1.2**：有结果的搜索页 `index,follow`，canonical 带归一后的搜索词；海阅有分页，第 2 页起 canonical 自引用（带 `page`），与列表页同口径。零结果、没输入、过短、过长 `noindex,follow`，canonical 为裸 `/search`；数据库出错、开关关闭 `noindex,nofollow`。不进站点地图，`robots.txt` 不屏蔽（否则抓取器看不到 noindex）。任何状态都不声明 hreflang。推翻了方案早先"一律 noindex"的定稿（那一版源于主控把 CPS v8.1.2 误记为"结果页 noindex"）。
2. **分页**（每页 20，与"全部作品"页同一个翻页组件）。生产实测常见题材词命中上千本（"love" 1,213、"billionaire" 1,125、"alpha" 1,015），照 CPS "只给前 20 条"会让 98% 的结果读者永远看不到。
3. **只搜书名**（文章标题，即卡片上显示的书名）。作者字段全站为空且属前台禁出字段；简介平均 900 多字，噪音大、成本高；CPS 也不搜简介。
4. **页头入口**方向按推荐（电脑文字 + 手机图标），**先出设计稿**，Owner 选定后再写页头（第二批）。
5. **上线开关做在后台"站点设置"，不用环境变量**，默认关。关闭时搜索页 404 且 `noindex,nofollow`。
6. **nginx 限流**：每 IP 每分钟 20 次（突发 10）+ 全站每秒 3 次（突发 10），与页面额度分开记账。

## 决定与理由（与 CPS 的差异）

| 项 | CPS | 海阅 | 理由 |
| --- | --- | --- | --- |
| 可见性 | `buildDramaArticleRouteWhere` 一族 | **原样复用 B-38 `public-list.ts` 的 FROM 与 WHERE**（`PUBLIC_LIST_FROM_SQL` / `publicListWhereSql` / `singleLocale`，只加 export） | 一把尺子。推广链接可用、seo_only/hidden、下架、软删、他语种、博客文章的排除全部由那一段负责，搜索不复制任何一条；真实库用例逐类构造反例，断言搜索结果 ⊆ 列表可见集合并与独立参照逐 id 相等 |
| 大小写 | SQLite 的 LIKE 只对 ASCII 不分大小写，把搜索词展开成最多 5 种大小写变体 | **数据库里 `lower()`**，不做变体 | 那是为 SQLite 造的兼容层；PostgreSQL 实测对俄语、法语、德语重音大小写都对 |
| 字符归一 | 只对搜索词做 NFKC | **搜索词与书名两边都在数据库里 `lower(normalize(x, NFKC))`** | 只归一一边会漏：泰语元音 "ำ"（U+0E33）NFKC 后拆成两个字符，书名里没拆，照着书名打字搜不到（生产实测 "ทำ" 只归一搜索词 0 本，两边归一 8 本）；日语 160 本、泰语 87 本书名受影响 |
| 查询长度 | 最长 64 | **最长 500（= `Article.title` 的 `VarChar(500)`）**，最短 2（ja/ko/zh 单个汉字/假名/谚文放行，照 CPS v8.1.1） | 64 会拒掉海阅 420 本书的完整书名（英语最长 100 字）；用例读取 `schema.prisma` 断言上限 ≥ 书名字段宽度 |
| 怎么查 | 零命中探针 + 全等/开头/包含三段查询逐段早停，程序里分档排序 | **一条查询**：分档（全等 1、开头 2、包含 3）→ 发布时间新→旧 → 编号升序，窗口函数 `count(*) OVER ()` 同时拿总数 | 三段查询是为 SQLite 的扫描成本设计的；本地与生产实测一条查询最坏约 125 毫秒、零命中约 60 毫秒，拆三段反而更慢 |
| LIKE 元字符 | 不转义，事后在程序里逐字比对丢行 | **数据库里转义**（先归一、再转义反斜杠 / `%` / `_`；全角 "％" 归一后才是 "%"） | 要分页、要准确总数，就不能事后丢行 |
| 分档比较 | — | 比较前 `btrim` 书名两端的空白与方向/零宽控制符（字符集作绑定参数） | 生产 12 本阿语书名首尾带方向控制符，不去掉就永远进不了 1、2 档 |
| 结果卡片 | 单独的搜索结果卡片 | **复用列表卡片**（`BookGrid` + `hydratePublicListCards`，补全、复核、不变量违例日志沿用） | 海阅前台类型约定"首页与聚合页共用同一种卡片，不做第二套形态" |
| 缓存 | 60 秒 / 200 条，时长可用环境变量改 | 数值照搬，**不加环境变量**（代码常量），复用 `bounded-ttl-cache` | 同 B-38 与相关推荐的既有裁定；零结果也缓存，出错不缓存；键 = 语种 + 页码 + 归一词（`\u0000` 分隔） |
| 分页标题 | 无分页 | 有结果的第 2 页起，`<title>` 与 og/twitter 标题加本地化翻页后缀（`meta.pageSuffix`，英文 ` - Page N`）；描述不加 | 第 2 页起可收录且 canonical 自引用，不加后缀就与第 1 页同名；与"全部作品"页、分类页同一口径（复核时补，主控 10-09 确认第 2 页起自引用口径） |
| 开关 | 环境变量 `FEATURE_SITE_SEARCH` | 后台"站点设置"字段 `siteSearchEnabled`，默认关 | Owner 10-09；本批只读 `isSiteSearchEnabled(settings)`，字段缺失按关 |

## 网址形态（写死，上线后不再改；网址冻结 2026-10-09 起）

- 路径：英语 `/search`，其它 14 个语种 `/{语种}/search`（语种码与现有前缀完全相同）；全小写 `search`；不带末尾斜杠。
- 参数：`q`（重复取第一个，服务器内部归一，地址栏保持读者提交的样子，**不做规范化跳转**）；`page`（第 1 页不带，第 2 页起 `&page=N`，N 为十进制正整数无前导零；参数顺序 `q` 在前 `page` 在后，与"全部作品"页同一个翻页组件拼法）；其它参数一律忽略。
- canonical 只声明，不跳转；超出页码 / 非法页码 404（新网址、从不收录）。
- **不改动任何已有网址、跳转、canonical、hreflang、站点地图、robots.txt；不加任何 redirect。** `/en/search` 会被现有 `/en/*` → 去前缀 308 规则带到 `/search`，那是现有规则的通用效果，规则本身不改。
- 翻页组件 `Pagination` 只加可选 `prefetch`，不传时与改动前逐字节一致（用例拿冻结的原样实现逐字节比较）；搜索结果页传 `prefetch={false}`，否则每显示一页结果浏览器会在后台顺带请求下一页，多跑一次查询。
- 语种切换：从搜索页切到目标语种的 `/search`，只带 `q`、去掉 `page`；其它页面的切换计划与 href 不变（用例钉住）。

## 防刷

nginx 模板新增只匹配 `/search` 与 `/{语种}/search` 的 location（**正则必须加引号**；放在页面类正则与 `location /` 之前），只挂 `cps_edge_search_ip`（每 IP 20r/m 突发 10）、`cps_edge_search_all`（全站 3r/s 突发 10）和现有训练类爬虫限流 `cps_edge_bot_page`，**不挂**任何页面或预取的额度。效果：刷搜索最多吃满搜索自己的额度，读者看书的额度不受影响；搜索对源站的压力有硬上限（全站每秒 3 次 × 最坏约 125 毫秒 ≈ 0.4 核）。仓库只改模板与校验（契约用例、docker 矩阵、变异），由发布方用既有安装器装到生产，与 HSTS 提级同一次安装。

## 上限与触发条件（方案第六节）

| 上限 | 数值 | 会不会藏掉结果 | 触发条件与门禁 |
| --- | --- | --- | --- |
| 每页本数 | 20 | 不会（分页能翻到全部） | 用例钉住"总数 = 全部命中、最后一页可达"；与 `BROWSE_PAGE_SIZE` 相等由用例钉住 |
| 结果总数 | 无上限 | — | 用例：构造 > 20 本命中，断言总数与页数 |
| 查询最短 / 最长 | 2 / 500 码点 | 不是上限，是输入门槛；500 = 书名字段宽度 | 用例读取数据库结构定义，断言上限 ≥ 书名字段宽度 |
| 缓存 | 60 秒 / 200 条 | 新上架的书最多晚 60 秒能搜到；刚下架的书最多 60 秒内还会出现在结果里（点进去是下架页） | 用例钉住常量；与 B-38 页脚分类同一档口径 |
| 数据库耗时 | 无硬上限 | — | 单次搜索数据库耗时 > 1000 毫秒记一条结构化告警 `site_search_slow`（不记搜索词）；用例钉住阈值与"不含搜索词" |
| 规模 | 无硬上限 | — | 复用 B-38 规模触发器（任一语种列表可见书 > 60,000 时 `scale-check` 退出 3）；届时评估搜索的三元组索引（`pg_trgm`，生产库可装但未装，装扩展需要超级用户迁移，现在不值得） |
| 搜索页收录量 | 无硬上限 | — | 发版后第 7 天由发布方 `site:pulsenovels.com/search` 看一次，**超过 500 条即提交 Owner 复议收录口径**；用例钉住"零结果/空查询/出错恒 noindex" |
| nginx 限流 | 见上 | 被限的访客看到 429 | 发版后第 1 天与第 7 天由发布方看一次搜索 location 的 429 占比（访问日志需 root 读）；非爬虫访客 429 占比超过 1% 即上调每 IP 额度；模板数值由 `public-cutover-edge.test.ts` 钉住 |

已知取舍（照 CPS 接受）："Alpha" 与 "alpha" 是两个可收录网址；任意子串都可能生成一个有结果的网址。搜索页不在站点地图、站内也没有指向带词搜索页的固定链接（只有读者自己提交和翻页链接），实际被发现的数量取决于外链。

## 后果

- 不需要迁移、不需要新索引、不需要新的数据库权限：搜索只读 `article` / `novel` / `promo_link`，web_app 已有 SELECT（真实库用例用真实 web_app 角色跑，scheduler_app 仍被拒）。
- 不加环境变量；开关由后台字段控制，合并后默认关，发版不改变前台任何行为。
- 回滚：后台关掉开关即下线（搜索页 404，下一个请求生效）；或整版回滚，nginx 新 location 可保留（应用返回 404 很快）。
- 验证入口：`bash scripts/run-site-search-postgres-verification.sh`（真实库）、`bash scripts/run-site-search-postgres-verification.sh --bench`（本机规模测量）、`bash scripts/preproduction/verify-nginx-matrix.sh`、`node scripts/preproduction/verify-public-cutover-mutations.mjs`。
