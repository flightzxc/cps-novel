# ADR-B38：公开列表改由数据库分页，分类归属落成投影表

- 状态：已采纳（Owner 2026-10-09 拍板方案决定 1～6；「再议 A」待 Owner 确认，确认前 v0.5.13 不发布）
- 日期：2026-10-09
- 范围：v0.5.13；分支 `fix/b38-db-pagination-v0513`（第一段：投影表与写入点）与 `fix/b38-db-pagination-v0513-read`（第二段：读取侧）
- 方案全文：`产品原型及文档/cps海阅/方案_B38根治_公开列表改数据库分页_v0.5.13_2026-10-09.md`（第零节为拍板结果与逐项对照 CPS）
- CPS 参照：`cps-admin` tag `v8.7.2`（peeled commit `c8c7d4ed66c42395a44811262afdb84bf29a8405`）

## 背景

首页、全部作品页、分类页、页脚与首页题材导航都先取"每个语种最新 240 本"（`PUBLIC_LIST_CAP`）进内存，再在程序里判推广链接可用、算分类归属、分页。10-06 全量发布 2.9 万篇后，英语全部作品页只显示 240 works，分类页只能翻到窗口内的书，站点地图只列窗口内有书的分类。这个上限是 08-18 写下、次日复核时"登记不阻断"的，没有写触发条件。

## 决定

1. **由数据库筛选、分页、计数**（照 CPS `getCategoryPageData` / `getTagPageArticles`）。原生 SQL 只取"当前页编号 + 总数"，卡片用既有 select 按编号补全、按原顺序排好。列表可见性只在 `src/lib/site/public-list.ts` 定义一次，首页、全部作品、分类页、页脚/导航、站点地图、站内链接、hreflang、404、作品数、分页共用。
2. **分类归属物化成 `novel_effective_tag`**（照 CPS `drama_effective_tag`：书、分类、来源、分数、排序位、计算时间；只收启用分类；全仓库只有 `src/server/tagging/effective-tag-projection.ts` 能写）。不物化不可行：现场按三套规则算，最大分类（英语 9,732 本）生产实测单次 5.0 秒，原因是上游映射支路先在全部语种展开 130 万行再过滤。卡片、详情页、章节页、相关推荐、站点地图的标签也改读这张表（CPS 前台只读投影），全站只剩一份归属数据。
3. **写入点同事务重算**（CPS 的五类：改映射、同步出现新标签、人工模式、自动打标写入、停用分类；另加建小说绑定书目）。目录同步按页重算本页已绑定的书（海阅的同步还会改语言范围、撤销书目软删，这两种也影响映射归属）。只写差异，稳定状态零写入。
4. **并发**：咨询锁 50212，全量对账独占、单本重算共享；单本重算另对书行加 `FOR NO KEY UPDATE`（按 id 排序）。调用方先咨询锁、后行锁。真实库复现过的三种问题（同书并发时旧快照覆盖、目录同步与后台改标签死锁、停用分类与重算死锁）因此排除。
5. **首次建表放在迁移里**（`20261009120000_b38_novel_effective_tag` 的 `B38_FIRST_BUILD` 段，维护窗口内、服务全停）。不照搬 CPS"另跑回填"：CPS 2026-08-26 那次发布卡在中途，生产停在"投影为空"。迁移段是规则 SQL 的逐字快照，静态用例钉住文本，真实库用例证明结果逐行相同。
6. **兜底**：站点地图刷新前先只读检查（不拿锁），有差异才拿独占锁对账。CPS 自己的教训是"靠穷举写入路径保证一致本身就是错的"；而"先检查"让稳定状态下站点地图刷新完全不拿锁，避免后台人工改标签撞上对账、超过 web_app 5 秒的 lock_timeout。
7. **推广链接"可用"在数据库侧完全等价**（`promoReadySql`：按 JS `String.prototype.trim` 的同一组 25 个空白字符 `btrim`，字符集作绑定参数）。不照搬 CPS 的 `promoUrl != ''`（CPS 已登记缺陷）。不改写入端、不回填（生产纯空白链接 0 条）。`isPromoReady` 仍是权威，渲染前逐行复核，复核丢行记 `public_list_invariant_violation`。
8. **页面级事实最多晚 60 秒**：页脚、首页题材导航、详情页标签可点、分类页 hreflang 读"每语种每分类本数"矩阵，web 侧用已移植的 CPS 有界 TTL 缓存（代码常量 60 秒，不加环境变量）。判定条件照 CPS `getFooterData`（启用 + 该语种至少一本可见），"实时"不照搬：CPS 一篇文章一个分类，这条查询便宜；海阅一本书多个分类，英语实时算一次约 40～50 毫秒（本机）。列表、作品数、分页、404 实时。
9. **不留任何列表上限**：`PUBLIC_LIST_CAP` 删除，博客列表同改（照 CPS blog-queries 的 skip/take + count）。深翻页随页数线性变慢，设触发器：任一语种任一分类超过 40,000 本，或任一语种列表可见超过 60,000 本 → 矩阵计算时记 `public_list_scale_threshold_exceeded`，`scripts/ops/effective-tag-projection.ts scale-check` 退出 3（发版检查用）；到时改游标翻页。

## 再议

- **A（发布前须 Owner 确认）**：重算"同事务直接算"vs CPS"发件箱 + 后台任务消费"。建议直接算：海阅的重算是一条集合 SQL（一本约 1 毫秒，全量生产约 1.5 秒热 / 3.9 秒冷），照搬发件箱要多一张表、一种新任务类型、改服务器 worker 白名单环境变量（回滚漏改 worker 起不来，v0.5.8/v0.5.9 同类问题），且主 worker 常被试读抓取占满会滞后。重算入口都收在 `effective-tag-projection.ts`，改判只动这一处。
- **B（不阻塞）**：首页题材导航照 CPS 改"运营勾选显示哪些分类"需要新字段与后台页面，另开单；本轮为"该语种全部有书分类"（英语 61 → 100 个，单行横滑不变）。

## 证据（要点）

- 生产只读：新规则 SQL 与改造前现场计算在全部 80,299 本书上逐本、逐分类、连顺序一致（自动标签开 184,981 行、关 131,226 行，0 处不一致）。
- 同一份合成数据（英语 13,000 本可见、大分类 9,835 本）新旧对比（本机中位数）：全部作品第 1 页 64.9 → 24.8 ms（且从 230 本 / 12 页变成 13,000 本 / 650 页）；大分类第 1 页 65.6 → 33.1 ms；小分类第 1 页 65.6 → 14.2 ms；页脚分类 63.9 → 1.9 ms（60 秒内，首次 51.4）；hreflang（4 个语种）140.7 → 0.02 ms（60 秒内，首次 48.7）；大分类最后一页（第 492 页）69.8 ms。
- 运行器：`run-effective-tag-projection`、`run-public-list`（含全码位推广链接等价、列表等价、一致性不变量、卡片标签读表等价、真实角色）等，skipped 均为 0。

## 后果与运维

- 迁移 24 条、表 58 张；新表权限：web_app / worker_app 增删改查，analyst_ro 只读，scheduler_app 无。
- 发版后：在 worker 容器执行 `tsx scripts/ops/effective-tag-projection.ts check`（worker_app），差异应为 0；`scale-check` 应退出 0。依赖镜像里的全局 tsx（Dockerfile runner 阶段）与 `scripts/` 目录。
- 回滚：镜像回到 v0.5.12 即可，新表与新索引留着无害（旧代码不读）。回滚期间改过的标签不会进表；再前滚后先跑 `check`，差异不为 0 再执行 `reconcile --apply --confirm RECONCILE-EFFECTIVE-TAGS`（生产写，逐条批准）；也会在下一次站点地图刷新时被兜底对账补齐。
- 运维脚本改映射/标签后须执行一次对账（`tests/backend/tagging/effective-tag-write-path-registry.test.ts` 登记为 `ops_script_requires_reconcile`）。
- 已知窗口：某分类最后一本书刚下架时，页脚/详情页最多 60 秒内还链向已 404 的分类页（UI 用例钉住这个偏差与过期后纠正）。
