## 1. 原规则（D-12，此前状态）

`PreviewChapterList.tsx` 头部曾写着四条硬约束：

1. 只列上游实际返回的章节。
2. **不宣称完整**——标题是"可试读章节"，不得出现"完整目录""全部章节"。
3. 这不是目录，是样章。
4. 没有章节就整块不渲染。

这四条里，第 2 条是本次修订的对象；第 1、3、4 条**维持不变**。

## 2. 运营诉求与冲突

运营原文要求：按 `Novel.totalChapterCount` 生成完整目录，第 4 章起标为"加密章节"，点击弹窗引导"继续阅读"跳转到推广链接。这与原规则第 2 条正面冲突——按总章数生成条目，就是在"宣称"这本书在本站有这么多章可看，即便读者点进去发现只是个锁。

评估文档（2026-09-28）给出三个选项：A（做但守住不伪造底线）、B（只加按钮不生成虚拟条目）、C（完全照运营原文，生成全部虚拟章节）。Owner 于 2026-09-29 选择 **选项 A**。

## 3. Owner 裁决（2026-09-29）：折中方案

修订后的规则，全部体现在 `PreviewChapterList.tsx` + `ChapterListBody.tsx` + `ContinueReadingModal.tsx`：

1. 🔴 **第 1 条不变，仍然不可协商**：真实的试读章节，即上游实际返回的那几章，照常列出，保持为可点击的链接（`<a href>`），组件不做任何拉伸或编造。
2. **新增**：`Novel.totalChapterCount` 大于真实章节数，并且这本书有 `readOnUpstreamHref`（推广链接）时，从下一个编号起追加"锁定章节"条目：
   - 只显示"第 N 章"加锁图标，**不编造章名**；
   - 每一条是 `<button>`，**不是 `<a>`，不生成任何网址**。点击后弹出确认弹窗，弹窗里的"继续阅读"按钮才跳 `readOnUpstreamHref`。
3. 标题固定为"章节列表"（`novel.chapterListTitle`），并在标题下方显示"共 N 章"（`novel.chapterListCount`，N = `totalChapterCount`）。**不得**使用"完整目录""全部章节"这类表述——这条底线原样保留，只是允许"列表本身可以包含锁定占位条目"。
4. 🔴 **服务端 HTML 最多渲染 30 条锁定条目**（`ChapterListBody.tsx` 的 `SERVER_LOCKED_CAP`），后面给一个"展开全部 N 章"按钮，由客户端在浏览器里按需生成剩余编号——不发请求、不新增路由，不把几千条数字写进首屏 HTML。
5. 列表最后加一个"阅读更多章节"按钮，同样跳 `readOnUpstreamHref`。
6. 没有推广链接的书：不追加锁定条目，也不渲染"展开全部"与"阅读更多章节"这两个按钮——真实章节链接的渲染方式与本次改动之前完全一致。
7. 🔴 **不新增路由；JSON-LD 里不为锁定章节生成任何条目**——锁定章节只是页面上的视觉占位 + 弹窗，从不出现在结构化数据或站点地图里。

原规则第 3、4 条（"这不是目录，是样章"、"没有章节就整块不渲染"）未被触碰。

## 4. 为什么这不是"伪造内容"

判定"是否伪造"的标准从来不是"要不要展示总章数"（总章数本来就是详情页元信息里的客观标量，早就在展示），而是**是否让读者以为自己能在本站点开一个不存在的东西看到真实内容**。折中方案的三处设计专门堵住这一点：

- 锁定条目是按钮不是链接：没有 URL，搜索引擎不会抓到、不会索引一个 404 或空页面；
- 锁定条目不显示编造的章名，只显示编号——不做"仿佛有真内容"的视觉暗示；
- 点击后立刻弹窗说明"继续阅读需要跳转"，不是把用户导向一个看起来像本站页面、实际是空壳的地方。

## 5. 章节页联动（B2）

章节页（`ChapterScreen.tsx`）除了上一章/下一章导航外，现在也嵌入同一个 `PreviewChapterList` 组件，读取同一份 `previewChapters`/`totalChapterCount`/`readOnUpstreamHref`（`ChapterView` 类型新增这两个字段，见 `src/features/public-ui/types.ts`）。规则与小说详情页完全一致——两处复用同一份实现，不允许出现"小说页守规则、章节页放水"的分叉。

## 7. 不变的底线（重申）

- 不编造章节内容（标题、正文）；
- 锁定条目永远不是可访问的网址；
- 零真实章节时整块不渲染；
- 不生成任何针对锁定章节的结构化数据或站点地图条目。

这四条是本轮修订后仍然"不可协商"的部分，任何后续改动都不得触碰。
