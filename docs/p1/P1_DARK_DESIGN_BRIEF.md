# 海外阅读 P1 · 用户端深色设计说明

> 出稿方：**ClaudeDesign 设计负责人**
> 实现方：前端开发负责人（Claude）
> 适用范围：**用户端（前台）**。后台不适用——后台按 CPS 现状保持浅色，见 `P1_ADMIN_PARITY_SPEC.md`。
> 本文件是设计口径冻结，不含组件实现。

---

## 1. 四条定调

1. **整体深色。** 前台以深色为基底，不是"支持深色模式"，而是**深色即默认形态**。
2. **ClaudeDesign 出稿。** 视觉稿、token、组件规格由 ClaudeDesign 定义，前端按稿实现，不即兴发挥。
3. **阅读器跟随系统。** 试读正文页按 `prefers-color-scheme` 跟随系统——**这是唯一的例外**，理由见 §3。
4. **不默认做浅色营销页。** 不为落地页/首页单独做一套浅色视觉。

---

## 2. 为什么整体深色

三个理由，按权重排序：

**一、内容形态决定。** 这是一个以长文本阅读为主的站——书详情、试读目录、试读正文。深色底 + 适度对比的正文色，长时间阅读的眼睛负担低于纯白底黑字，尤其在移动端夜间场景（海外阅读的主要流量时段）。

**二、与 CPS 短剧站区隔。** CPS 前台是暖米色系（`--site-bg: #f7f0e4`、`--site-primary: #265f63`，见 `globals.css`）。海外阅读域名独立、品牌可不独立，但**视觉上必须让人一眼看出是另一个产品**——否则运营与 SEO 上都会混淆。

**三、成本更低。** 只做一套主题，比"浅色为主 + 深色适配"少一半的设计与回归面。V1 阶段这个节省是实的。

---

## 3. 唯一例外：阅读器跟随系统

**范围**：试读正文页（`/…/chapter/{n}`）的**正文阅读区**。

**行为**：

```css
/* 正文阅读区，且仅此区域 */
@media (prefers-color-scheme: light) { /* 浅色纸感 */ }
@media (prefers-color-scheme: dark)  { /* 深色，与站点基底一致 */ }
```

**为什么单独破例**：阅读正文是用户停留最久的场景，而阅读偏好高度个人化且**已经由系统设置表达过了**。强制深色对习惯浅色阅读的用户是负担。其余页面（详情、目录、聚合、首页）都是浏览而非沉浸阅读，统一深色不会造成同样的负担。

**边界纪律**：
- 跟随范围**只有正文阅读区**——页头、页脚、CTA、导航始终深色，不随系统翻转；
- V1 **不做**站内手动主题切换器（无账号体系，偏好无处持久化；`localStorage` 方案留 Post-V1）；
- 跟随不影响 SEO：两种配色下 DOM 与文本完全一致，只有 CSS 变量不同。

## 4. 设计 Token（ClaudeDesign 定义，冻结结构不冻结色值）

**结构冻结**：token 命名与层级由本文件定义；**具体色值由 ClaudeDesign 出稿时给定**，前端不得自行取色。

```
--novel-bg              页面基底
--novel-bg-elevated     卡片/浮层底
--novel-fg              主文本
--novel-fg-muted        次要文本
--novel-fg-subtle       第三级文本（元信息、时间戳）
--novel-border          分隔线
--novel-primary         主色（品牌）
--novel-primary-hover
--novel-accent          强调色（CTA）
--novel-accent-hover
--novel-danger          错误/下架态
--novel-success

/* 阅读区专用，跟随系统 */
--reader-bg
--reader-fg
--reader-fg-muted
--reader-selection
```

**约束**：
- 命名前缀 `--novel-*` 与 `--reader-*`，**不复用 CPS 的 `--site-*`**（避免搬运时串味）；
- 所有颜色只能来自 token，组件里禁止硬编码色值；
- token 定义在 `src/styles/`（Claude 所有权）。

---

## 5. 对比度与可访问性（硬要求）

| 项 | 要求 |
| --- | --- |
| 正文对比度 | ≥ **WCAG AA 4.5:1** |
| 大字号标题 | ≥ 3:1 |
| CTA 按钮 | 文字与底色 ≥ 4.5:1；hover 态不得降低对比度 |
| 焦点态 | **必须有可见 focus ring**，键盘可达 |
| 纯黑禁用 | 基底**不用 `#000`**——纯黑配白字在 OLED 上会产生光晕拖影，正文用深灰阶 |
| 纯白禁用 | 正文**不用 `#fff`**，降低眩光 |

**共享基元的双主题义务**（呼应 `P1_MODULE_OWNERSHIP.md` §6）：`src/components/ui/**` 的每个基元必须同时在后台浅色与前台深色下可用。实现方式是基元只消费语义 token（`--surface` / `--on-surface` 之类），由各自的 scope 提供具体值——**不是在基元里写 `dark:` 分支**。

## 6. V1 页面清单与视觉重点

| 页面 | 视觉重点 |
| --- | --- |
| 首页 | 轮播（复用 CPS `home_carousel_*` 数据形态）+ 书籍卡片网格。封面是唯一高饱和元素，其余克制 |
| 小说详情 | 封面 + 标题 + 简介 + 元信息（语种/章数/收费起始章/题材标签）+ **主 CTA** + 试读入口。**不展示作者/国家/完结**（字段恒为 NULL） |
| 试读目录 | 章节列表。**只列上游实际返回的章节**；不宣称全书目录；**不按 `allEpis` 造无标题占位** |
| 试读章节 | 正文阅读区（跟随系统）+ 上/下章导航 + 底部固定 CTA + 面包屑回详情 |
| 语言聚合 / 题材聚合 | 卡片网格，与首页同构 |
| `/go` 跳转 | 无 UI（302） |
| 下架 / 撤回页 | 稳定、克制、不报错感；`takedown` 走 410 |

### 两条内容纪律进入设计

1. **不展示不存在的字段。** 作者、国家、完结状态在上游 `UPSTREAM_FIELD_NOT_FOUND`，设计稿里**不得出现这三个位置**——留了位就会有人想填。
2. **目录不撒谎。** 目录页文案不得出现"全部章节""完整目录"等表述；对外语义是"可试读章节"。

## 7. 排版

| 项 | 取值 |
| --- | --- |
| 正文字号 | 移动 17–18px / 桌面 18–19px |
| 行高 | **1.75–1.9**（长文本阅读的关键参数） |
| 正文宽度 | 最大 **68–72 字符**，超出加边距 |
| 段间距 | ≥ 1em，不用首行缩进（西文为主） |
| 字体 | 系统字体栈优先；**不引入 Web Font**（首屏性能 + 无 CDN 依赖） |
| 长章分块 | 超长单章**段落分块渲染**，**不做前端翻页器**（立项书 §3.4.6 已排除） |

---

## 8. 明确不做（V1）

- ❌ 浅色营销页 / 浅色落地页
- ❌ 站内主题切换器（无账号体系，Post-V1 再议）
- ❌ 完整阅读器交互（翻页、字号调节、夜间模式开关、阅读进度）
- ❌ Web Font、动效库、骨架屏动画（首屏性能优先）
- ❌ 作者页 / 国家页 / 完结榜 / 连载榜的任何视觉位
- ❌ 评论、评分、收藏的 UI

---

## 9. 交付顺序

```
ClaudeDesign 出 token 色值 + 三个关键页视觉稿（首页 / 详情 / 章节）
   ↓
前端落 src/styles/ token 与基元适配
   ↓
按页实现（P2 阶段）
```

**P1 阶段只需交付**：token 结构（本文件 §4）、对比度规格（§5）、页面清单（§6）、排版参数（§7）。**具体色值与视觉稿在 P1 末或 P2 初给出，不阻塞 P1 的后端工作。**
