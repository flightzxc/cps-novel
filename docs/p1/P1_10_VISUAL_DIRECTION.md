## 1. 这份文档负责什么

它回答四个问题：站长什么样、为什么长这样、每个页面由哪些块组成、以及哪些东西**永远不许出现在页面上**。

它不回答的：URL 长什么样（尚未冻结）、数据从哪来（本轮全部是本地假数据）、后台长什么样（另一个任务）。

一条贯穿全文的纪律：**页面上的每一个字段，都必须是分销接口确实会返回的字段。** 上游官网上有而接口没有的东西——作者、评分、阅读量、完结状态、国家、章节发布日期、同作者作品——一律不进设计稿，也不为它们预留任何位置。理由在第九节。

## 2. 主方向：墨与纸

一句话定义：

> **页面是墨，行动按钮是纸，封面是全站唯一的颜色。**

三种材质，三种职责，不越界：

**墨**是页面的基底。它不是纯黑，是一种带着轻微蓝调的深墨色——像夜里的墨水，不像关掉的屏幕。所有层级（页面 → 卡片 → 悬浮态）都在这个墨色里往上抬一点点亮度，抬得很克制，靠间距而不是靠灰阶台阶来分组。

**纸**是行动。主行动按钮是一块温暖的、低彩度的纸色，压着深墨色的字。它不是一颗高饱和的胶囊，是一张纸。这一条同时解决了两件事：它在深色页面上有天然的最高对比度（实测 14.5:1），并且它主动放弃了饱和度——于是它永远不会和封面抢眼。

**色**只属于封面。上游的言情封面本身就是高饱和的金色、红色、紫色。界面如果也用高饱和强调色，两者会打架，页面会变吵。所以界面把彩度让出去：全站唯一的高饱和区域是封面图本身。

这三句话可以推导出后面几乎所有决定，包括为什么按钮不是全圆角、为什么不用 emoji 做小标题、为什么正文用衬线体。

### 方向必须做到的七条（对照任务要求）

| 要求 | 本方向如何落实 |
| --- | --- |
| 深色、克制、内容优先 | 界面主动放弃彩度，把彩度留给封面；界面元素只有墨与纸两种材质 |
| 阅读类比视频类更松的密度 | 移动端 2 列、桌面 5 列（竞品普遍是 3 列 / 6 列）；区块间垂直留白加长一档 |
| 不依赖通栏宽幅 banner | 主推位是「大封面 + 大标题 + 大留白」的编排块，只需要一张封面，见第五节 |
| 首页主推位靠封面、排版、层级、留白建立气场 | 主推标题用衬线体大字号 + 收紧字距；上方留白远超常规；一条细规线 + 小号眉标做编排感 |
| 阅读器是体验差异化核心 | 阅读器有独立 scope、独立浅深色、四项可调排版参数；见第十一节 |
| 不用 emoji 装饰小标题 | 小标题只有文字 + 一条细规线；四个竞品全部用 emoji，这是最省力的区隔点 |
| 不复制上游或短剧站的品牌识别 | 不用蓝色开卷标、不用橙红、不用亮黄、不用品红；不用全圆角胶囊按钮；不用整页模糊背景 |

## 3. 为什么这个方向适合我们当前真实拥有的字段

我们的详情页在最精简的真实情况下只有七样东西：封面、书名、简介、语种、总章数、大约三条实际可试读章节、两个行动按钮。标签可能整块不存在。

对一个「靠堆元数据撑版面」的设计来说，这是灾难。对本方向不是，原因有三条：

**第一，本方向的版面重量来自排版，不来自元素数量。** 书名用衬线体、用接近显示级的字号、独占一行——它自己就能撑起半个首屏。竞品把书名压成 14px 两行截断，是因为它们的页面上还有作者、评分、集数、播放量要排。我们没有这些，正好把字号还给书名。

**第二，简介被当作正文对待，而不是当作说明文字。** 它是这个页面上唯一的长文本，给它阅读级的字号、行高和行长（约 68 字符）。它一个人就能占掉一屏的三分之一，而且是有内容的三分之一，不是填充物。

**第三，可试读章节区块是第二个重心。** 它有自己的小标题、自己的计数说明、自己的列表节奏，承担页面下半部分。三条章节看起来少，但把它做成「样章」的形态——每条带章号、章名、可点——而不是做成「目录」的形态，密度就是合适的。

反过来说，本方向明确禁止用下面这些方式补密度：编造元数据、留空占位槽、放「作者：暂无」这类文案、用装饰性插画填空、用假的推荐位撑长度。**版面空，就用留白和字号解决，不用内容解决。**

## 4. 元信息区：流式，只渲染真实存在的字段

元信息（语种、共 N 章）采用流式自适应排布：有几项排几项，中间用细分隔点，一项也没有时整行不渲染。

这不是为了将来加字段方便——**本方向明确不为任何未知字段预留固定槽位**。流式的理由只有一个：不同的书在同一时刻拥有的字段就可能不同（比如标签有的有有的没有），版面必须对「少一项」是自然的，而不是留出一个空洞。

标签同理：**允许公开的站点标签为空时，整个标签区块消失**，不留标题、不留空框、不留占位 chip。

## 5. 为什么不依赖宽幅美术物料

这是四轮竞品分析里最硬的一条结论。

做通栏出血 Hero 的两家，用的都是**专门制作的宽幅物料**：一家用的是剧照（约 16:9），另一家用的是定制 banner（约 6:1，标题排版直接烘焙进图）。唯一绕开这个问题的那家，用的是卡片式主推——只需要一张竖版封面。

我们的图源只有上游封面，是竖版的。要做通栏，只有三条路，全都不通：

| 做法 | 为什么不行 |
| --- | --- |
| 把竖封面拉伸成宽幅 | 变形，或者裁掉封面上烘焙的书名，两种结果都不能接受 |
| 把封面模糊放大铺底再叠一张清晰小封面 | 背景亮度随封面变化，正文对比度不可控——这正是我们判定为反面教材的那家的做法；且移动端渲染成本高 |
| 自建美术管线做定制 banner | 我们没有这条管线，也不在本期范围内 |

所以本方向**结构上就不需要宽幅图**。主推位是这样一个块：

左边一张封面，尺寸给得很大（桌面约占内容宽度的三分之一），上下留白远超常规；右边是眉标、书名、元信息、简介摘录、两个按钮。移动端上下堆叠，封面居中且不铺满。

气场来自三处，都不花钱：**封面被给到足够大的尺寸**、**书名被给到足够大的字号**、**上下被给到足够多的空白**。

## 6. 如何避开「近黑底 + 海报网格 + 高饱和胶囊」

这三件套四个竞品全中。逐条拆解：

**近黑底 → 有色墨底。** 竞品的基底是中性近黑（观感在纯黑到 `#0d0d0d` 之间），我们的基底带明确的蓝调（色相约 220°，低彩度）。并排看得出是两种东西：一个是「关掉的屏幕」，一个是「墨」。同时它满足「不用纯黑」的硬要求。

**海报网格 → 松排书架。** 三处改动：列数减少（移动 3→2，桌面 6→5）、槽宽加大、卡片下的书名给到可读字号而不是缩略图标签字号。另外封面加一道极细的内描边，让它看起来是「一个有厚度的物件」而不是「一块贴上去的图」。

**高饱和胶囊 → 低彩度纸片。** 主按钮是纸色（温暖、低彩度、亮），圆角用中等值而不是全圆。全圆角胶囊是 App 商店语言；中等圆角矩形是出版物语言。次按钮是描边式，边框强度做到可辨识门槛以上。

**额外一条：不用 emoji 做小标题。** 四个竞品的小标题全部是 `🔥`/`🚀` 开头。我们的小标题只有文字，右侧可选一个文字型入口，下方一条细规线。这一条几乎不花成本，但区隔感非常强。

**再一条：正文用系统衬线体。** 四个竞品全站无衬线。系统衬线在所有目标平台上都自带，零 Web Font 成本，但立刻把观感从「短视频 App」推向「出版物」。书名和阅读正文用衬线，界面控件仍用无衬线。CJK 语种下若无可用衬线字族，自动回落无衬线，不做任何补偿。

## 8. 两个作用域

站点和阅读区是**两套独立的颜色作用域**，不是同一套的明暗变体。

**站点作用域**恒为深色，不跟随系统，不提供切换。页头、页脚、导航、卡片、按钮全在这个作用域里。

**阅读作用域**只覆盖章节正文的阅读区。它默认跟随系统偏好；用户可以手动改成浅色或深色，手动选择优先级高于系统。三态语义是「跟随系统 / 浅色 / 深色」，跟随系统是默认值。

边界纪律：阅读作用域**只包住正文阅读区**。同一个章节页上，页头、页脚、章节导航、行动按钮始终在站点作用域里，不随系统或用户选择翻转。这样做的好处是，浅色阅读模式下页面仍然明确属于本站，而不是变成一张来路不明的白纸。

## 9. 数据边界：只允许出现的字段

这一节是硬约束，优先于任何视觉考量。

**首页 / 聚合页卡片只允许**：封面、书名、允许公开的站点标签（可为空）、语种（设计需要时）。

**详情页只允许**：书名、封面、简介、语种、总章数、实际可试读章节、允许公开的站点标签、站内开始试读按钮、公开跳转码对应的正式阅读按钮。

**章节页只允许**：章号、章名、正文、上一章 / 下一章、所属小说、当前试读范围（形如「试读 1 / 3」）。

**禁止出现，且禁止预留固定槽位**：作者、评分、阅读量、完结状态、国家、章节发布日期、同作者作品、全书阅读进度百分比、按总章数伪造的完整目录、分成比例、渠道真实码、应用下载模块、用户体系 / 评论 / 收藏 / 赛事 / 用户生成内容。

上游官网上存在这些字段，与我们无关——官网跑的是它的内部完整数据，分销接口不返回这些。它们的状态统一记为：**仅存在于上游官网 / 分销接口不提供 / 不是本期设计输入**。

另有两条内容纪律：

1. **原始来源标签不得直接进前台。** 只有明确允许公开的站点标签才能展示；没有时整个标签区块消失。
2. **目录不撒谎。** 可试读章节区块的标题、说明文字、结构化数据一律不得出现「完整目录」「全部章节」这类表述；对外语义只有「可试读章节」。总章数可以作为一个客观标量展示，但绝不据此生成任何章节行。

这些约束由自动化测试守住——测试会渲染全部屏幕并扫描输出，命中禁用词即失败。

## 10. 页面结构

页面壳按块描述，不绑定具体路由。**正式 URL 结构尚未冻结**（语种段的取舍仍是待决项），因此本轮的屏幕全部实现为与路由无关的功能组件，由一组明确标记为「仅供开发预览」的临时路由承载。这些临时路由整体不可索引，不进入 sitemap，也不进入任何 SEO 契约。

### 首页

页头 → 主推位（大封面 + 眉标 + 大字书名 + 元信息 + 简介摘录 + 两个按钮）→ 作品网格（小标题 + 卡片网格）→ 页脚。

没有轮播。首页只推一本，理由是我们没有可信的排序信号，轮播多本会暗示一个并不存在的排名。

### 小说详情

页头 → 主要书籍信息区（封面 + 书名 + 元信息 + 标签）→ 行动区 → 简介 → 可试读章节区块（锚点 `#preview-chapters`）→ 可选的内容推荐结构（本轮不接数据，无数据即整块不渲染）→ 页脚。

不建独立目录路由，不生成目录页 canonical。

### 章节阅读页

页头 → 轻量书籍归属条（小封面 + 书名链接 + 试读范围）→ 章节标题与阅读设置入口 → 阅读区（阅读作用域）→ 章节导航（上一章 / 下一章）→ 章末行动区 → 页脚。

每个章节页都是独立页面结构，自身指向自身的 canonical（本轮只做结构，实际的元数据在内容阶段接入）。

### 语言 / 题材聚合

页头 → 页面标题与说明 → 卡片网格（与首页同构）→ 页脚。聚合页与首页共用同一个卡片组件，不做第二套卡片形态。

### 下架 / 撤回

页头 → 状态说明块 → 返回入口 → 页脚。

语气要求：**稳定、克制、不制造错误感**。不用红色大叉、不用「出错了」这类措辞，用平静的陈述句说明这本书当前不可阅读，并给一条回到首页的路。撤回态与下架态文案不同但视觉相同。实际的 HTTP 状态码由内容阶段的路由层负责，本轮只做页面形态。

## 11. 阅读器

阅读器是本产品唯一能明显优于上游网页端的地方——上游自己的网页阅读器没有任何阅读设置。这不是附加功能，是主方向的核心论据之一。

**本轮（P1-10）交付**：阅读区浅深两套视觉、主题三态控件、字号 / 行高 / 页宽控件、移动端设置面板、正文排版、章末行动区与章节导航。

**下一任务（P1-11）交付**：偏好持久化、滚动位置恢复、章节切换不整页刷新。

**本轮对下一任务的义务**：控件必须有明确的状态接口，不能做成静态图形；设置变更必须真实改变阅读区外观；必须保留客户端状态与本地存储的接入点。因此本轮的控件是**真实可用但不持久化**的——刷新后回到默认值，这是预期行为，不是缺陷。

正文排版参数：

| 参数 | 默认 | 可调范围 |
| --- | --- | --- |
| 字号 | 18px | 16 / 18 / 20 / 22 |
| 行高 | 1.8 | 1.6 / 1.8 / 2.0 |
| 页宽 | 68 字符 | 60 / 68 / 76 |
| 段间距 | ≥ 1em，不首行缩进 | 不可调 |

默认值落在既有设计说明给定的区间内（正文 17–19px、行高 1.75–1.9、行长 68–72 字符）。可调范围可以超出该区间，这正是可调的意义。

超长单章按段落分块连续渲染，**不做前端翻页器**。

设置面板形态：移动端从底部升起的面板，桌面端锚定在设置按钮下方的浮层。可用 Esc 关闭，可键盘操作，打开时不遮挡正文顶部。

## 12. 版面与密度

| 项 | 移动 390 | 桌面 1440 |
| --- | --- | --- |
| 内容最大宽度 | 全宽减两侧 20px | 1200px 居中 |
| 卡片网格列数 | 2 | 5 |
| 网格槽宽 | 16px | 28px |
| 区块垂直间距 | 48px | 80px |

对照竞品：移动端普遍 3 列、桌面普遍 6 列。我们各减一到两列，是刻意的密度降档，对应「阅读类比视频类更松」。

**封面比例集中定义为一个可调 token**（当前取 3 / 4）。真实上游封面资产尚未量过，比例可能需要改；改这一个变量即可，全站不得有第二处硬编码比例。

圆角三档：小 6px（标签）、中 10px（按钮、卡片）、大 14px（面板）。**没有全圆角**。

## 13. 品牌占位规则

正式 Logo 尚未交付。本轮使用：文字占位符 `BRAND_PLACEHOLDER`，配一个无品牌含义的几何标记（一个带内嵌竖条的圆角方形，纯几何，不表意）。

Logo 槽位尺寸固定，16 / 24 / 32 / 40 四档全部预留并在组件中可用。页头使用 32 档，页脚使用 24 档。

**正式 Logo 到位后，只替换标记资产与文字，不重构页头。** 因此槽位是固定尺寸的方形容器，标记以何种形式填充与布局无关。

禁止：自行生成正式 Logo；用 emoji 当 Logo；因占位标记而做出不可逆的布局决定。

## 14. 备选方向摘要：书架

保留一个备选，供后续如果主方向被否时切换。

**概念**：把首页做成一面书架。基底改为更中性的深灰墨（去掉蓝调），封面网格用细横规线一排排隔开，像书架隔板；强调色改为单一的冷调青灰，主按钮改为描边式而非填充式。

**优点**：更中性、更工具感，做多语种时不会因为暖色调而显得偏某个市场；细规线的结构感能在没有元数据的情况下提供额外的秩序感。

**风险**：一、没有填充式主按钮，行动召唤强度明显下降，而我们的跳转按钮直接关联收益；二、横规线在移动端两列布局下会显得局促；三、中性深灰更接近竞品的近黑基底，区隔度不如主方向；四、去掉暖调后，界面与暖色系封面之间缺少温度对比，封面会显得更「贴」在页面上。

**结论**：不采用。记录在此，若主方向在真实封面资产接入后出现冲突再评估。
